# 18. 监控与指标收集

## 概述

本章是讲义收束：让你把“架构设计”落到“可度量运行”。

## 指标注册入口

当配置开启 GRAFANA_METRICS_ENABLE 时，registrar 会挂载 /metrics 并初始化 OTel。

入口在 [backend/core/registrar.py](../backend/core/registrar.py) 的 register_metrics。

## 指标定义与打点

指标定义见 [backend/common/observability/prometheus.py](../backend/common/observability/prometheus.py)。

常见指标类别：

1. 请求总量（Counter）。
2. 请求耗时分布（Histogram）。
3. 在途请求数（Gauge）。
4. 异常次数（Counter）。

AccessMiddleware 与 OperaLogMiddleware 是关键打点位置。

## 监控数据流

```mermaid
flowchart LR
  A[应用 /metrics] --> B[Prometheus 抓取]
  B --> C[时序存储]
  C --> D[Grafana 展示]
```

## 实战观测维度

建议优先看四类面板：

1. 吞吐：QPS。
2. 延迟：P95/P99。
3. 错误：异常率、5xx。
4. 资源：连接池与 Redis 响应。

## 告警建议

1. 错误率超过阈值。
2. 延迟异常抬升。
3. 在途请求长期高位。
4. 关键依赖（DB/Redis）不可用。

## 小结

到本章为止，你已经形成完整闭环：

1. 架构分层可维护。
2. 运行行为可观测。
3. 问题定位可追踪。

这也是企业级后端工程化的核心能力。
