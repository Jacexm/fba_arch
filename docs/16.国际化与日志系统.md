# 16. 国际化与日志系统

## 概述

本章关注两项横切能力：

1. 国际化（请求级语言选择 + 文案翻译）。
2. 日志（结构化输出 + trace_id 关联）。

## 国际化流程

核心文件：

1. [backend/common/i18n.py](../backend/common/i18n.py)
2. [backend/middleware/i18n_middleware.py](../backend/middleware/i18n_middleware.py)
3. [backend/locale/zh-CN.yml](../backend/locale/zh-CN.yml)
4. [backend/locale/en-US.json](../backend/locale/en-US.json)

流程：

1. 中间件解析 Accept-Language。
2. 写入上下文当前语言。
3. 响应码与异常文案通过 i18n.t 获取对应语言文本。

## 日志系统

核心在 [backend/common/log.py](../backend/common/log.py)。

设计目标：

1. 统一入口（标准 logging 转 loguru）。
2. 统一格式（包含 request_id/trace_id）。
3. 统一输出（控制台 + 文件分流）。

## trace_id 关联

请求链中生成 trace_id 后，日志 filter 会把 request_id 注入日志记录。这样可把一次请求的多条日志串起来。

Mermaid：

```mermaid
flowchart LR
  A[HTTP Request] --> B[Context 生成 trace_id]
  B --> C[业务日志输出]
  C --> D[log filter 注入 request_id]
  D --> E[stdout/file]
```

## 最佳实践

1. 错误日志与访问日志分离存储。
2. 文案 key 稳定，不把整句文本当 key。
3. 在异常返回中保留 trace_id，便于问题回溯。

## 小结

国际化与日志让系统从“能运行”升级到“可服务多语言用户、可追踪问题”。
